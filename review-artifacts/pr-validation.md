PR series validation, 25 September 2026

Eight draft PRs are open and attached to the task. The implementation plans, dependencies and links are in [pr-plans.md](pr-plans.md). Every implementation branch uses a separate worktree, has its remote and upstream configured, and contains signed commits attributed to Christoph Pader. All eight worktrees are clean. The original NitroSQLite checkout retains its pre-existing untracked documentation files.

The text fix, Unicode property-name fix, positional result storage, grouped statement reuse and private SQLite symbols were checked in a combined Release app on an iPhone 13 Pro running iOS 26.5.2 and a Samsung SM-G977B running Android 12. The original code reproduced the embedded-NUL truncation and corrupted non-ASCII keys. The patched app passed 24 focused checks on each device. These cover ordinary and prepared text, distinct Unicode keys and cache reuse, repeated getter mutation, duplicate aliases, BLOB lifetime after statement finalization, populated and empty prepared results after a schema change, omitted batch bindings, rollback and rejection of an all-empty batch.

The initial local comparison helper used object serialization without sorting keys. That produced two extra false failures on the iPhone baseline. The helper was corrected before the patched runs. The actual text and Unicode baseline failures remain separately visible in the raw records. These local checks supplement the repository tests; they are not represented as runs of the complete repository harness.

The performance comparison used one warmup and five measured rounds for each workload, with case order rotated. The baseline includes the text and Unicode fixes. The comparison build adds positional query results and batch statement reuse together. Fully consumed ordinary reads had medians of 255.25 ms before and 174.76 ms after on iPhone, and 4,136.62 ms before and 2,343.99 ms after on Samsung. Grouped asynchronous batches of 1,000 rows changed from 13.37 to 7.55 ms on iPhone and 47.57 to 15.87 ms on Samsung. Android optimized samples vary substantially. Full samples, ranges, source revisions and conditions are in [pr-performance.md](pr-performance.md) and [pr-performance-summary.json](pr-performance-summary.json). These are workload-specific combined measurements, not isolated attribution to either PR or a device-fleet result.

Private SQLite symbols also passed mobile coexistence checks. On iPhone, Nitro now reports version 3.49.0 and source ID beginning `4a7dd425`, while OP reports source ID beginning `bf7c7f30`, corresponding to its separate 3.53.4 engine. Expo reports its own `3ce993b8` source ID. OP still reports Expo's 3.50.3 version string on iOS because those two libraries retain an unprefixed version-data symbol. The PR isolates Nitro and does not claim to fix OP versus Expo. The linked iOS binary contains separate private and unprefixed function and version-data symbols, recorded in private-ios-symbols.txt. Android also reports distinct engines. Vector extension isolation passed the host coexistence test; vectors were disabled in the mobile benchmark app.

The final benchmark smoke used the published packages from dependency PR #1: NitroSQLite 10.0.0, Nitro Modules 0.37.1, OP SQLite 18.2.5 and Expo SQLite 57.0.3. It used the runner and case modules from benchmark PR #3, including prerequisites #1 and #2, in the existing local review app. Its local wrapper selected 50 rows and read repetitions, one warmup, three measured rounds and a 50 ms cooldown. Full run metadata and evidence paths are in [pr-benchmark-validation.json](pr-benchmark-validation.json).
